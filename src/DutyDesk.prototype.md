# 值班工作台版面原型（可拋棄）

要驗證的問題：工讀生打開工作台，能否立即找到待回覆、待交接及待領物品，並知道下一步？

使用者已確認「待辦優先」。沿用暖黃配色、原始透明 Logo 與既有辦公室介面的脈絡，製作三種結構：

- **A／待辦清單**：一次選一類待辦，集中處理。新增物品、行政聯絡與新增交接固定在右側。
- **B／分類看板**：待回覆、待交接、待領物品各有一欄，同時掌握各類工作；每欄可捲動。
- **C／找老師辦事情**：先找到老師，再集中看他的訊息、物品及交接；未指定老師的交接另有入口。

資料是固定的虛構情境：5 位老師、3 位待回覆、4 筆交接、7 件物品，含一位尚未綁定教師及一筆發送需檢查提醒。所有操作只存在記憶體，重新整理或重設情境即恢復；不使用 LINE、資料庫或瀏覽器持久儲存。

## 開啟

最簡單的方式：下載 `DutyDesk.prototype.preview.zip`，解壓縮後用 Chrome 開啟 `duty-desk-prototype.html`。底部箭頭或鍵盤左右鍵可切換 A／B／C；輸入欄位內不攔截方向鍵。三個比較網址以 `?variant=A`、`?variant=B`、`?variant=C` 表示，重新整理會保留版面選擇並重設示範資料。

使用原始碼時，在此原型分支的專案資料夾開啟 PowerShell，先載入 Node.js：

```powershell
fnm env --shell powershell | Out-String | Invoke-Expression
fnm use --install-if-missing 24
npm.cmd ci
npm.cmd run prototype:desk
```

瀏覽 `http://127.0.0.1:5181/?variant=A`。要重新產生單檔 HTML：

```powershell
fnm env --shell powershell | Out-String | Invoke-Expression
fnm use --install-if-missing 24
npm.cmd run prototype:desk:html
```

成品在 `.local/prototype/duty-desk-prototype.html`。

## 建議試用

1. 剛開始值班：找出誰在等回覆，回覆其中一位老師。觀察待回覆數量減少。
2. 換下一班：看交接內容，標記完成並填寫完成人姓名。
3. 老師來領件：核對老師與物品，確認領取；需要時在更多操作中重新通知或取消登記。
4. 收到新物品：選老師、物品類型，編輯通知文字，預覽後模擬通知；未綁定教師可僅登記物品。
5. 在不重設資料的情況切換 A／B／C，比較同一批待辦在哪一版最容易理解。底部狀態區會顯示最新數量及剛完成的操作。

原型只比較資訊層級、入口與版面；詳細通知去重、權限、歷史篩選及復原等業務規則，仍以正式網站為準。

## 比較結論（2026 年 11 月 24 日，台灣）

使用者試用後表示：「這三種版本都沒有原本的好」。本輪結論為保留既有值班工作台，不將 A／B／C 套用至正式網站。

完整原型保留於 `prototype-duty-desk-layouts` 分支，作為比較依據。正式工作台的原本排列維持不變；後續若需改善，先釐清原版的具體操作問題，再評估局部調整。

本次僅記錄選版結果，沒有變更正式網站、資料庫、通知規則或部署設定。
